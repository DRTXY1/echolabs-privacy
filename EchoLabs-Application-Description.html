🎙️ EchoLabs

Application Description

Last updated: August 2026

EchoLabs is a Twitch Extension that brings AI text-to-speech to a broadcaster's stream. Viewers use Bits or Channel Points to have a short text message read aloud live, through an OBS Browser Source overlay. Broadcasters choose their own text-to-speech provider and connect it with their own API key — Bits and Channel Points transactions are handled entirely by Twitch.

1. Supported TTS providers

A broadcaster can connect one or more of the following, each with their own account and API key:

ElevenLabs, TTS Monster, Microsoft Azure AI Speech, Google Cloud Text-to-Speech, Amazon Polly, OpenAI, Cartesia, Fish Audio, Deepgram, LMNT

2. Broadcaster setup

1Activate the extension

The broadcaster activates EchoLabs on their channel from the Twitch Creator Dashboard (Extensions → My Extensions). Once active, Twitch shows a Configure link that opens EchoLabs' own configuration panel.

2Connect a TTS provider

Under Settings → TTS Providers, the broadcaster picks a provider tab and enters that provider's credentials (an API key for most; a region for Azure; an access key pair + region for Amazon Polly). Each tab links directly to that provider's own key/account page. Credentials are validated live and stored server-side only — never exposed to viewers.

3Add voices

The broadcaster adds voices from a connected provider's voice library and assigns a Bits or Channel Points amount to each — a voice can also be made free. Channel Points require the channel to be connected via Twitch's own Channel Points integration, available only to Affiliate/Partner channels (a Twitch platform restriction, not an EchoLabs one).

4Customize behavior and overlay

The broadcaster can adjust overlay appearance (colors, font, size, position, transparency), set a per-message cooldown, manage a custom word blacklist on top of a built-in one, restrict who may send messages (everyone, subscribers, VIPs, or moderators), and optionally enable a chat bot announcement or a leaderboard of top senders.

5Add the overlay to OBS

The configuration panel provides a unique, channel-specific Browser Source link, added in OBS (or similar software) — this is where the generated audio plays and the message is shown visually during the stream.

3. Viewer flow

1Pick a voice

The viewer panel shows the voices the broadcaster made available, each labeled with its Bits/Points amount, or "Free".

2Share identity

The first time, the viewer is shown a Grant Permissions button, which opens Twitch's own native identity-share dialog. Sharing identity is required before a message can be sent — enforced on the server for every request, not just in the UI.

3Compose and send

The viewer types a message and confirms it through Twitch's native Bits dialog, or a Channel Points redemption. An optional "Send Anonymously" checkbox (if enabled by the broadcaster) hides the sender's display name on the overlay only — the server still always knows who sent the message, for moderation and cooldown purposes.

4Playback

Within a few seconds, the message is turned into audio by the broadcaster's connected provider and played through the OBS Browser Source overlay, with an animated on-screen display of the message and sender.

4. Data handled

  • Message text is sent only to the broadcaster's connected TTS provider, for synthesis — not stored beyond what's needed for moderation/cooldown logic and, only if enabled, a leaderboard.
  • Viewer identity (Twitch user ID / display name) is required to send a message, used for moderation, cooldowns, and optional overlay display.
  • Provider API keys are entered by the broadcaster, stored server-side only, and never returned in full to the browser.
