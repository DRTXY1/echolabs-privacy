🎙️ EchoLabs

Reviewer Walkthrough

For Twitch Developer Console review

EchoLabs is a Twitch Extension that lets viewers pay with Bits or Channel Points to have a short text message read aloud via AI text-to-speech, played live on stream through an OBS browser-source overlay. Broadcasters choose their own TTS provider (ElevenLabs, TTS Monster, Azure, Google Cloud, Amazon Polly, OpenAI, Cartesia, Fish Audio, Deepgram, or LMNT) and supply their own API key for it — EchoLabs itself never charges anything; all TTS costs are billed directly by the broadcaster's chosen provider.

The block below is meant to be copied into the Twitch Developer Console's "Testing Instructions" field. The detailed sections that follow are for reference, or for a reviewer who wants more context on any specific step.

1. What you'll need before testing

  • A Twitch channel with the extension installed/activated (Creator Dashboard → Extensions → My Extensions → Activate on a test channel).
  • OBS (or any software that supports a "Browser Source"), since the TTS audio and on-screen message only appear there — the extension panel itself is silent by design (it's a config UI, not the output surface). A plain browser tab works too for testing purposes; OBS is only needed for an actual broadcast.
  • An account with at least one supported TTS provider and an API key for it. ElevenLabs' free tier is enough for a quick test. The Configuration panel requires at least one valid provider key before it lets you add voices or accept any payment.

2. Finding the Configuration page

The extension is set up with "Custom/My Own Service" as its configuration hosting method (Capabilities tab in the Developer Console), so Twitch shows a "Configure" link/button next to the extension once it's activated on a channel — that link opens our own Configuration page (config.html). If that link isn't visible, double-check the extension is actually activated (not just installed) on the test channel.

3. Broadcaster setup (Configuration panel)

  1. Open the extension's Configuration view via the "Configure" link described above.
  2. Go to the Settings tab → TTS Providers card. Providers are shown as a row of tabs, ElevenLabs first. Click a tab, enter the required field(s) for that provider (just an API key for most; Azure also needs a region, Amazon Polly needs an access key pair + region). Each tab has a "How do I get the credentials?" link that opens a short guide with a direct link to that provider's key page.
  3. Click "Save & validate". The panel checks the key live against the provider's API before saving — an invalid key shows a clear error and nothing is stored.
  4. Go to the Voices tab, click "Add voice", pick the provider (if more than one is configured) and select a voice from the list — pulled live from that provider's own voice library. Set a Bits price for it (e.g. 100).
  5. Every change in this panel saves automatically as you type or toggle something — there is no separate "Save" button anywhere. A small status indicator ("Saved…") confirms this.
  6. (Optional) Set a Channel Points price on the same voice. This only becomes active once the channel is connected to Twitch via the "Channel Points" card and a matching Custom Reward syncs successfully — see the limitation note in section 7.

4. OBS Browser Source setup

The Configuration panel's header shows a ready-to-copy OBS Browser Source link, unique to that channel. Add it in OBS as a Browser Source (recommended size 1920×1080), or simply open it in a normal browser tab for testing — this is where the TTS audio plays and the animated on-screen message/voice card appears when a viewer redeems.

Example of the link format (this one is channel-specific and will not work on a different test channel — every broadcaster's panel shows their own):

https://6vw92ljoheooxl8ltin1sv7fgv8146.ext-twitch.tv/6vw92ljoheooxl8ltin1sv7fgv8146/0.0.1/f1f786772bf0fa3987402ce5c9671c75/live_config.html?t=39e2308819b792a6abe4ba96efffdd36

5. Testing the viewer flow

  1. Open the extension's viewer panel (mobile view, or the panel view shown under the video player).
  2. Pick a voice tile — each shows its Bits price (or "Free" if priced at 0, or "Unavailable" if it's Channel-Points-only and the channel isn't connected yet).
  3. Identity step: the first time, the panel shows a "Grant Permissions" button. Clicking it opens Twitch's own native identity-share dialog. Sharing identity is required before any message can be sent — this is enforced server-side, not just hidden/shown in the UI, so it cannot be bypassed by manipulating the client.
  4. Optional "Submit Anonymously" checkbox: appears only once identity has been shared, and only if the broadcaster has turned this option on. It hides the sender's name from the on-stream overlay display — it does not bypass identity verification; the server always knows exactly who sent the message, for moderation and cooldown purposes.
  5. Type a short message and confirm the Bits payment through Twitch's native Bits dialog.
  6. Confirm the message is read aloud and displayed in the OBS Browser Source (or the plain browser tab from section 4) within a few seconds.
  7. Broadcaster pause test: in the Configuration panel, click the pause pill next to the language selector (top right, "Pause extension"). Confirm the viewer panel immediately shows a clear "paused" notice and no longer allows sending messages, until unpaused again.

6. Data & privacy notes for review

The extension requires Twitch identity sharing (user_id) to send a message — enforced on every server request, not just in the UI, and never bypassed by the "Anonymous" display option described above.

No TTS message text is stored beyond what's needed for moderation/cooldown logic and (optionally, only if the broadcaster enables it) a leaderboard of top senders.

TTS provider API keys are entered by the broadcaster and stored server-side only; they are never exposed to viewers or returned in full to the browser — the Configuration panel only ever shows a masked placeholder (••••••••) for an already-saved key.

7. Known platform-level limitations (not bugs)

  • Channel Points require the connected channel to have Twitch Affiliate or Partner status — a Twitch platform restriction on Custom Rewards, not something the extension can work around. On a non-eligible test channel, the "Connect with Twitch" flow in the Configuration panel surfaces a clear in-panel error explaining this rather than failing silently.
  • The OBS Browser Source link is per-channel (it carries an embedded, channel-specific token), so it cannot be shared or reused across different test channels.
